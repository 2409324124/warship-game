## 一、约定

### 坐标系（最容易搞错，先读）

游戏世界是 three.js 右手系：**+Y 向上，+Z 船首（北），+X 西**。

> 为什么 +X 是西而不是东：右手系里 `(+x) × (+z) = −y`，而"上"是 +y，所以 `(+x, +z, +y)` 不构成
> `(东, 北, 上)` 的右手系。只有 `(+z) × (+x) = +y`… 换言之 **−x 才是东**。舵向、航向读数、海图
> 都已经按这个对齐过，不要在 Blender 里"纠正"它。

Blender 也是右手系，但 **Z 向上**。官方 glTF 导出器做 Z-up → Y-up：

```
(x, y, z)_blender  →  (x, z, −y)_gltf
```

| Blender 里 | 导出后 / 游戏里 | 含义 |
| --- | --- | --- |
| +X | +X | 西（左舷） |
| **−Y** | **+Z** | **船首方向** |
| +Z | +Y | 上 |

**在 Blender 里把模型朝 −Y 建模**（默认"前视图"正对你的方向），导出后就是船首朝 +Z，
与程序化船体完全一致。

### 单位与原点

- **1 Blender 单位 = 1 米**，`scene.unit_settings.scale_length = 1`
- **原点**：船用件放在**水线面、船体中心**——与程序化船体一致（`y = 0` 是水线，船体沿 ±Z 前后展开）
- 岛屿地标原点放在**底面**（`y = 0` 贴地）

### 命名与落点

| 类型 | 目录 | 命名 |
| --- | --- | --- |
| 挂船小件 | `public/models/props/` | `<舰key>_<部件>.glb`，如 `us_bb_floatplane.glb` |
| 岛屿地标 | `public/models/landmarks/` | `<类型>.glb`，如 `lighthouse.glb` |

工作文件 `.blend` 放 `art/blender/`，**不入库**（已在 `.gitignore` 排除，二进制只留导出结果）。

### 导出设置

- 格式 **glTF Binary (.glb)**
- 勾 **+Y up**（导出器默认）
- 导出前 **Apply Transform**
- 朝向在 Blender 里一次性摆好（机头 −Y），导出后不要再补旋转
- 材质用 **Principled BSDF**（游戏侧是 `MeshStandardMaterial`，PBR 直接对应）
- 贴图尽量嵌进 .glb，避免多文件

## 二、游戏当前上下文

### 这是什么

浏览器里的二战舰炮对战游戏（Vite + TypeScript + three.js r180）。
第一关：**一艘美军战列舰 vs 三艘日本驱逐舰**，铁底湾夜战。

### 模型现在是怎么来的（关键）

**全部是代码程序化生成的，没有任何外部资源。** 两套数据驱动：

| 数据 | 位置 | 作用 |
| --- | --- | --- |
| 船体线型 | `src/sim/hull.ts` | 站位放样：舯部 U 形（`p=3.4`）、艏部 V 形（`p=1.15`），生成蒙皮 + 甲板 |
| 舰船部件表 | `src/sim/ships.ts` | 声明式清单，建模和**命中盒共用同一份数据** |
| 炮塔/炮管规格 | `src/sim/guns.ts` 的 `TS` 表 | `len/h/w/bl/br/n/cf/fs/ss/rs/ears/hood` |
| 武器参数 | `src/sim/guns.ts` 的 `GUNS` 表 | 射程、初速、散布、装填 |

部件表里的构件类型（改舰船外观就改这些）：

```
Bx 方块（上层建筑主体，支持 rf/rr 艏艉圆角、fs 前倾、ta 顶部收分、win 舷窗带）
Cy 烟囱（rake 后倾、ov 椭圆化、pipe 烟管、cap 烟囱帽）
Ms 桅杆（tri 三脚桅、yards 横桁、top 桅顶、radar）
Pl 平台    Tt 鱼雷发射管    Aa 高炮（o/b2/b4/j2/j3/ha/ha2）
Sl 探照灯  Rf 测距仪        Dr 指挥仪   Bt 吊艇/小艇
Cp 弹射器  Cr 起重机        Gm 固定炮座  Dc 深弹架   Tu 炮塔（挂在 tur 数组里）
```

渲染侧：`src/render/shipModel.ts` 把上面这些翻译成几何体，`src/render/shipView.ts` 每帧同步
位置/摇摆/炮塔转动/沉没。**船体、上层建筑、舰炮都是箱体与回转体的堆叠**——这正是程序化擅长的，
也是"哪些该在 Blender 里做"的判断依据。

### 六艘舰（`src/sim/ships.ts` 的 key）

| key | 舰 | 主炮 | 副炮 | 当前状态 |
| --- | --- | --- | --- | --- |
| `us_bb` | 北卡罗来纳级 | 3×III 16"/45（艏2艉1） | 10×II 5"/38 | 第一关玩家舰，出镜最多 |
| `jp_bb` | 金刚级 | 4×II 14"（艏2艉2） | 12×I 6" 舷侧炮廓 | 宝塔桅层级偏少 |
| `us_ca` | 新奥尔良级 | 3×III 8"/55（艏2艉1） | 4×II 5" | 副炮应为 8 门单装 |
| `jp_ca` | 高雄级 | 5×II 8"（艏3艉2） | 2×II | 副炮应为 4×II；鱼雷应为 4×II |
| `jp_dd` | 吹雪级 | 3×II 127mm | — | 第一关敌舰，3 艘同屏 |
| `us_dd` | 弗莱彻级 | 5×I 5"/38 | — | 相对最完整 |

主炮/副炮配置有 `test/ships.test.ts` 的数据测试锁着（3 座三联 16 寸、10 座双联 5 寸左右各五等），
改配置会红——**这是故意的**，改之前先确认资料。

### 接口（当前是" dormant"）

`src/render/assets.ts`：

```ts
loadModel(name)                       // 加载 /models/<name>.glb，缺失时返回 null 不报错
mountProps(parent, props, deckAt)     // 按 { model, z, y?, x?, ry?, scale? } 挂到父节点
```

- **现在没有任何地方 import 它**，所以不进包、不生效（构建产物 591 kB，与加它之前完全一致）
- GLTFLoader 是懒加载的，只在第一次真正加载时才拉进来
- 文件缺失 → 静默跳过，游戏照常跑

**接线步骤（等有 .glb 了再做，现在不用动）**：
1. `src/sim/ships.ts` 的 `ShipSpec` 加一个可选字段 `props?: { model; z; y?; x?; ry?; scale? }[]`
2. `src/render/shipView.ts` 构造末尾调用 `mountProps(this.group, spec.props, z => deckY(spec, z))`
3. 舰船数据里加 `props: [...]` 一行
4. 地标：在 `src/main.ts` 里遍历一份地标数组，`loadModel` 后 `scene.add`

### 命中盒

命中判定用的是 `spec.L / B / F / top` + `segHitShip()` 的盒体测试，**与渲染几何无关**。
所以装饰件做得再精细也不会影响命中——这也是"Blender 件只管好看"的底气。

## 三、要做什么

### 分工原则（先想清楚再动手）

- **程序化就能做好的，不要在 Blender 里做**：烟囱数量/位置、舰桥层数与收分、副炮数量与型号、
  炮塔尺寸与炮管粗细——这些是数据行 + `TS` 表，改完命中盒自动同步、能立刻跑测试。
- **Blender 只做代码很难表达的有机/异形件**：
  - 水上侦察机 + 浮筒（曲面机身、机翼）
  - 舰桥圆弧围壁与舷窗带
  - 格子桅 / 宝塔桁架
  - 烟囱帽喇叭口、排烟管
  - 救生艇 / 小艇的曲面船壳
  - 螺旋桨、锚、系缆桩
  - 岛屿地标：灯塔、椰树、栈桥、沉船

### 优先级建议（按第一关出镜频率）

1. `us_bb` 北卡罗来纳 —— 玩家舰，全程在画面里
2. `jp_dd` 吹雪 —— 第一关 3 艘敌舰
3. `jp_bb` 金刚 —— 宝塔桅是辨识度核心
4. `jp_ca` 高雄 —— 巨大舰桥
5. `us_ca` 新奥尔良
6. `us_dd` 弗莱彻 —— 已相对完整

### 资料核对结果（**未经渲染验证，仅供参考**）

按历史资料比对部件表得出的差异，动手前最好再核一遍：

| 舰 | 差异 |
| --- | --- |
| `us_bb` | 两根烟囱（z=12、z=−5）→ 北卡级实际只有**一根**大烟囱，且与塔式舰桥一体化 |
| `us_ca` | 副炮 4×II 5″ → 实际为 **8 门单装 5″/25**（左右各 4） |
| `jp_bb` | 6″ 副炮 12 门 → 实际 **14 门**；宝塔桅应 7–9 层（现 5–6） |
| `jp_ca` | 副炮 2×II → 实际 **4×II 12.7 cm 高炮**；鱼雷 2×IV → 实际 **4×II** |
| `jp_dd` | 舰桥层次偏少；鱼雷管缺旋回盘/护盾 |
| `us_dd` | 基本正确，只差细节件 |

### 已知限制（影响"怎么判断做得对不对"）

目前**没有**几何互穿检测、没有粒子与舰体的碰撞、没有正交/线框检视模式。
所以判断一个部件做得对不对，现阶段只能在 Blender 里直接看，或者导出后靠游戏里的透视截图——
都不够。补上这几项（模型体检工具、检视模式、特效碰撞）是另一件事，不在这个工作区的范围里。

## 四、快速上手

```bash
# 1. 在 Blender 里建模，工作文件存
#    art/blender/<名字>.blend
# 2. 朝 −Y 建模，1 单位 = 1 米，原点水线/船体中心
# 3. 导出 glTF Binary (.glb)，+Y up，Apply Transform
#    → public/models/props/<舰key>_<部件>.glb
#    → public/models/landmarks/<类型>.glb
# 4. 接线（见上文"接线步骤"），在舰船数据里加 props 一行
```

游戏跑起来：`npm run dev` → http://127.0.0.1:5173
验证：`npm test`（37 项）、`npm run typecheck`、`npm run build`、`npm run smoke`（无头截图 + 探针）
